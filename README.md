# QQPet r31 服务端与登录器

**本程序仅供配合 QQPet 桌面客户端在本机使用。** 请在运行客户端的同一台电脑上启动服务端，客户端通过 `127.0.0.1` 连接。

本项目重建 QQ 宠物桌面客户端所需的本地服务端。仓库提供 Node.js 服务端、Windows 登录器、客户端补丁源码及配套校验工具。服务端处理登录、宠物养成、社区与家园、动作下发和存档。

## 安装本机服务端

本版本的服务地址为 `127.0.0.1`。网页和资源下载使用 HTTP 端口 `80`，社区目录使用原生 TCP 端口 `443`，登录使用 HTTPS 端口 `18443`。启动前请确认这些端口可由本机服务端监听。

1. 准备 Node.js 24 和 Python 3.11 或更高版本，在含有 `start-server.mjs` 的仓库根目录打开终端。下列命令中的 `python` 在 Windows 上可用 `py -3`，在 Linux 上可用 `python3`。
2. 按根目录的 `resources-manifest.json` 准备 r31 运行文件。清单的 `coreFiles` 列出全部 659 项运行文件，其中一部分项目配置随源码提供。请自行备齐其余原版配置、网页、脚本、插件及程序下载包。`files` 列出另需自行收集的 7,312 项服务端素材，包括动作 SWF、图片、音效及含媒体的下载 ZIP。
3. 把所需文件放在各条目 `path` 指定的位置。路径从仓库根目录计算，保留目录层次与大小写。例如，动作文件应位于 `server/config/assets/Action/102common/1022000001.swf`。每条记录附有字节数和 SHA-256。清单列出的 ZIP 须保留完整归档及其原有字节。
4. 核对本地文件。如果校验器报告缺失、大小有误或哈希不符，按输出的相对路径补齐对应版本后再运行。

   ```sh
   python verify-resources.py .
   ```

5. 核验全部通过后检查装配，然后启动服务端。首次装配会生成本机数据库和登录配对文件。

   ```sh
   node start-server.mjs --check
   node start-server.mjs
   ```

## 连接客户端

玩家还需自行准备与上述本机地址、端口配套的 r31 Windows 客户端程序、皮肤、宠物动作、游戏场景、Flash 组件和原生插件。使用 `client/pair-client.py` 校验已有的 `80/443` 客户端目录，并用本机服务端的登录证书指纹生成一份单独的客户端副本。原始 r31 客户端归档采用另一组端口。[客户端准备与配对](client/README.md)

## 服务端目录

| 路径 | 用途 |
| --- | --- |
| `start-server.mjs`、`tools/complete-release/` | 源码启动入口、装配检查和运行管理 |
| `server/src/` | 登录、游戏协议、宠物玩法、社区、存储和管理后台 |
| `server/config/` | 服务端端点、玩法配置、动画开关和下载资源配置 |
| `server/assets/`、`server/resources/`、`server/config/assets/` | 按清单存放页面、动作、游戏画面和客户端按需下载的文件 |
| `tools/local-login/`、`client/` | 登录器源码、构建脚本、客户端配对与补丁校验 |
| `tls/`、`client-login.json` | 首次装配生成的本机证书、私钥及客户端配对配置。客户端配对仅使用 `client-login.json` |
| `data/` | 本机生成的账号库、存档、运营配置和日志 |
